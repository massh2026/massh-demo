# MASSH デモ2（カメラを使わない版）

東京理科大学 野田キャンパスの学食・学内コンビニ・周辺の飲食店の「いまの混雑」と「待ち時間」が分かるサービスの試作です。
データはすべて架空です（学食とコンビニの名前以外の店名・メニュー・価格・位置は作りもの）。

混雑は次の3つの方法で集めます。

| 場所 | 測り方 | デモでの再現方法 |
|---|---|---|
| 学食（カナル・赤レンガ） | 席のQRコードでチェックイン | 席を押す・QRコードをスマホで読む・デモ操作でまとめて変える |
| 学内コンビニ | Bluetoothの電波の数から人数を推定 | Pythonのセンサー（`sensor/ble_counter.py`）か、デモ操作のスライダー |
| 周辺の飲食店・カフェ | お店の人がボタンで入力 | 「お店の方」の画面（PINはデモ操作の画面にあります） |
| 更新が止まっているお店 | 利用者の「空いてた／混んでた」投稿（位置情報で確認） | お店のページの投稿ボタン |

必要なものは **Python 3**（班のデモを動かすのに使っているもので大丈夫です）と **Chrome か Edge** だけです。追加のインストールはいりません。

---

## 1. 動かす（まずはこれだけ）

### Windows
1. zip を展開します（デスクトップなど、好きな場所でOK）。
2. フォルダの中の **`start.bat` をダブルクリック**します。
3. ブラウザが自動で開き、`http://localhost:8000/` が表示されます。

黒い画面（コマンドプロンプト）は開いたままにしておきます。止めるときは黒い画面で `Ctrl + C` を押すか、画面を閉じます。

「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」を押します。
「Windows セキュリティの重要な警告」（ファイアウォール）が出たら「プライベートネットワーク」にチェックを入れて「アクセスを許可する」を押します（スマホから開くときに必要です）。

### Mac
ターミナルでこのフォルダに移動して、次を実行します（`start.command` をダブルクリックしてもOK）。
```
python3 serve.py
```

### コマンドで起動する場合（Windows）
```
cd ダウンロードした場所\massh-demo2
python serve.py
```

> **`index.html` をダブルクリックして直接開いても動きません。** 必ず `start.bat`（または `python serve.py`）から開いてください。
> ブラウザの安全のしくみで、ファイルを直接開くとプログラムの読み込みが止められるためです。

## 2. 画面の一覧

| 画面 | URL | 内容 |
|---|---|---|
| さがす（ホーム） | `/index.html` | いま入れるお店、場面別の絞り込み（1時間の昼休み・空きコマのカフェ・予算ランチ・部活後の夜ご飯）、一覧／地図、並び替え |
| お店のページ | `/shop.html?id=canal` など | 混雑と待ち時間とその計算方法、次の授業に間に合うか、学食の席の状況、メニュー、お得情報、利用者の投稿、おすすめ点数の内訳 |

| デモ操作 | `/demo.html` | データのリセット、デモ時刻、Bluetoothと席のシミュレーション、PIN一覧、デモの台本 |

| 発表用の画面 | `/presenter.html` | スマホの画面とお店のタブレットの画面を並べて表示（プロジェクター用） |

## 3. 発表のしかた

1. 発表の直前に **デモ操作 →「デモデータを初期状態に戻す」** を押します。いまの時刻を基準にデータが作り直されます（前の日のデータのままだと、全部「情報が古い」になります）。
2. 夜に練習するときは **デモ操作 →「デモ時刻」** を `12:10` などにすると、「3限に間に合う」の表示を昼休みの状態で見せられます。
3. 教室で利用者の投稿を見せるときは **デモ操作 →「位置の確認を省略する」** をオンにします（オフのままだと、お店から100m以上離れているので投稿できません。それ自体も「いたずら投稿を防ぐしくみ」として見せられます）。
4. **`/presenter.html`（発表用の画面）** をプロジェクターに映し、右のタブレットでボタンを押すと、左のスマホの表示が変わる様子を見せます。
5. 台本はデモ操作の画面のいちばん下にあります。

## 4. Bluetoothセンサーを動かす（学内コンビニ）

PCのBluetoothで周りの機器を数え、その台数を画面に送ります。機器の識別番号は保存も送信もせず、台数だけを送ります。

```
pip install bleak
python sensor/ble_counter.py
```

- `serve.py` を起動したまま、**別の黒い画面**で実行します。
- 10秒ごとに「検出 ◯台 → 送信しました」と出て、数秒後に学内コンビニの混雑とレジ待ち時間が変わります。
- 推定人数は「台数 × 0.6」（`js/data.js` の `ble.coef`）です。実際の人数と見比べて係数を調整すると、発表で「校正した」と説明できます。
- PCにBluetoothがない、またはうまく動かないときは、Bluetoothを使わない練習モードで試せます。
  ```
  python sensor/ble_counter.py --simulate
  ```
- そのほかのオプション：`--interval 5`（送る間隔の秒数）、`--rssi -70`（電波が強い＝近い機器だけ数える）

## 5. 席のQRコード

- **デモ操作 →「席のQRコードを表示・印刷する」**（`/qr.html`）で、学食の席ごとのQRコードを表示・印刷できます。
- `serve.py` で開いていれば、スマホから開けるPCのアドレス入りで自動的に作られます。
- 画像ファイルが欲しいときは Python でも作れます。
  ```
  pip install "qrcode[pil]"
  python tools/make_qr.py http://192.168.x.x:8000
  ```
  （`192.168.x.x:8000` は、`serve.py` を起動したときに「スマホ・タブレットで」と表示されるアドレス）

## 6. スマホから開く

`serve.py` を起動したときに表示される「スマホ・タブレットで」のアドレス（例：`http://192.168.1.23:8000/`）を、**PCと同じWi-Fiにつないだ**スマホで開きます。

- **ローカルモード（初期設定）では、スマホとPCのデータは別々です。** スマホで押したボタンはPCの画面には反映されません。PCとスマホで同じデータを見せたいときは、次の「Firebaseモード」にします。
- 1台のPCだけで見せる場合は、発表用の画面（`/presenter.html`）を使えば、ローカルモードのままでもスマホとタブレットの連動を見せられます。
- 大学のWi-Fiは、端末どうしが通信できない設定になっていることがあります。つながらないときは、スマホのテザリングにPCとスマホの両方をつなぐか、Firebaseモード＋GitHub Pagesにしてください。

---

## 7. スマホとつなぐ（Firebaseモード）

Firebase（Googleの無料のデータベース）を使うと、どの端末で押しても全員の画面がリアルタイムで変わります。**無料の「Spark」プランのまま使います。クレジットカードの登録や、有料の「Blaze」プランへの切り替えはしないでください。**

1. https://console.firebase.google.com/ を開き、Googleアカウントでログインして **プロジェクトを作成** します（名前は `massh-demo` など。Googleアナリティクスはオフでよい）。
2. 左のメニューから **Firestore Database** を開き、**データベースを作成** します。ロケーションは `asia-northeast1（東京）` を選びます。
3. Firestore の **ルール** タブを開き、このフォルダの `firestore.rules` の中身をすべて貼り付けて **公開** します。
4. プロジェクトの概要（ホーム）に戻り、**ウェブアプリを追加**（`</>` のアイコン）します。ニックネームを入れて登録すると、`const firebaseConfig = { apiKey: ..., ... };` という設定が表示されます。
5. `js/firebase-config.js` をメモ帳などで開き、`export const firebaseConfig = null;` の `null` の部分を、表示された `{ ... }` に置き換えて保存します。
   ```js
   export const firebaseConfig = {
     apiKey: "AIza....",
     authDomain: "massh-demo-xxxxx.firebaseapp.com",
     projectId: "massh-demo-xxxxx",
     storageBucket: "massh-demo-xxxxx.appspot.com",
     messagingSenderId: "123456789012",
     appId: "1:123456789012:web:abcdef123456",
   };
   ```
6. ブラウザを再読み込みします。右上の表示が **「Firebase 共有中」** になれば成功です（はじめて開いたときに初期データが自動で入ります）。

Firebaseモードでの Bluetooth センサーは、そのままの使い方（`serve.py` 経由）でも、`serve.py` を使わず直接 Firestore に送る方法でも動きます。
```
python sensor/ble_counter.py --firebase-project massh-demo-xxxxx
```
（`massh-demo-xxxxx` は firebaseConfig の `projectId`）

> **注意**：`firestore.rules` は授業のデモ用に「だれでも読み書きできる」設定です。発表が終わったら、Firebase のプロジェクトを削除してください。
> 本番では Firebase Authentication でログインしたお店だけが書き込めるようにし、センサーは秘密鍵（サービスアカウントキー）を使う firebase-admin で書き込みます。秘密鍵のファイルは GitHub に上げないでください。

## 8. ネットに公開する（GitHub Pages・任意）

Firebaseモードにしたうえで GitHub Pages で公開すると、`https://〜` のURLで、どこからでも誰のスマホでも開けます（他の班の人に自分のスマホで触ってもらえます）。

1. GitHub で新しいリポジトリを作り、このフォルダの中身をアップロードします（「Add file」→「Upload files」）。
2. リポジトリの **Settings → Pages** で、Branch を `main`、フォルダを `/ (root)` にして保存します。
3. 数分後に `https://ユーザー名.github.io/リポジトリ名/` で開けます。
4. QRコードのページ（`/qr.html`）を公開URLで開けば、公開URL入りのQRコードになります。

※ `https` で開くと、スマホでも位置情報を使った投稿の確認が動きます。

## 9. 中身を書き換える

| ファイル | 中身 |
|---|---|
| `js/config.js` | 授業の開始時刻（**いまは仮の値です**）、「情報が古い」とする時間、席の自動退席の時間、点数の重みなど |
| `js/data.js` | お店・メニュー・価格・位置・PIN・学食の席の数 |
| `js/seed.js` | 「デモデータを初期状態に戻す」で作られる混雑の状態 |
| `js/logic.js` | 混雑レベル・待ち時間・おすすめ点数・授業に間に合うかの計算 |
| `js/store.js` | データの保存（ローカル／Firebaseの切り替え） |
| `js/pages/*.js` | 画面ごとの処理 |
| `css/style.css` | 見た目 |
| `serve.py` | ローカルのWebサーバー（センサーの中継つき） |
| `sensor/ble_counter.py` | Bluetoothセンサー |
| `tools/make_qr.py` | QRコード画像の作成 |

### 主な計算のしかた
- **学食**：使用中の席の割合で判定（30%未満＝空き／60%未満＝やや混み／80%未満＝混雑／それ以上＝満席）。退席を押し忘れても40分で自動的に空席に戻ります。
- **コンビニ**：Bluetoothの台数 × 0.6 ＝ 推定人数。レジ待ちは「推定人数 × 30秒」。
- **飲食店**：待ち時間は「待ち組数 × 1組あたりの分数（お店が設定）」。
- **情報が古い**：最終更新から60分以上たったお店は満席扱い。30分以内の利用者の投稿があれば、それを参考値として表示します。
- **おすすめ順の点数**：鮮度点（10分以内50点／30分以内30点／60分以内10点）＋ 空き点（空き30点／やや混み15点）＋ 条件点（予算・人数が合えば各10点など）。こまめに更新するお店ほど上に出ます。
- **授業に間に合うか**：往復の徒歩 ＋ 待ち時間 ＋ 一番早いメニューの提供時間 ＋ 食事15分 が、次の授業の開始までに収まるか。

## 10. うまく動かないとき

| 症状 | 対処 |
|---|---|
| 画面が真っ白／何も表示されない | `index.html` を直接開いていないか確認し、`start.bat`（`python serve.py`）から開き直す |
| `python` が見つからないと出る | Python をインストールする（https://www.python.org/ 。インストール時に「Add python.exe to PATH」にチェック） |
| ポートが使用中と出る | 別の番号で起動する：`python serve.py 8100` |
| 全部のお店が「情報が古い」 | デモ操作 →「デモデータを初期状態に戻す」 |
| 地図が出ない | インターネットにつながっているか確認（地図だけネットが必要。一覧はオフラインでも動きます） |
| スマホから開けない | PCとスマホが同じWi-Fiか確認、ファイアウォールで Python を許可、大学のWi-Fiならテザリングを試す |
| 右上が「Firebase 共有中」にならない | 画面上部の赤いメッセージを確認。`firebase-config.js` の貼り付け、Firestore の作成とルールの公開を確認 |
| 文字の形がふつうのゴシック体になる | フォントはネットから読み込んでいます。オフラインのときは PC のフォントで表示されます（動作には影響なし） |
